# Test plan — Cosmos mobile native iOS E2E (run7)

Build: repo `15222de6` (branch devin/1789889944-mobile-polish-e2e), packaged `target/package/Cosmos.app` (v0.2.79, ad-hoc signed), engine embedded listening `ws://127.0.0.1:27654`.
Mobile: `apps/mobile` dev-client (native build via `expo run:ios`) on iPhone 17 sim `D0B64A8A-D5F1-4668-8FFC-A86B400AF527` (**iOS 26.5**), JS served by Metro.

Sim substitution: the originally-booted UDID `8E780854` is an iPhone 17 on **iOS 27.0**, which this Xcode 26.6 could not build for (xcodebuild saw zero eligible destinations: "iOS 26.5 is not installed"). Fix was `sudo xcodebuild -downloadPlatform iOS` (8.5 GB component install) — after it, both iPhone 17s became eligible; the already-booted iOS-26.5 iPhone 17 was used.

Environment notes (hard constraints, verified):
- No agent CLI is installed on this Mac (no claude/codex/opencode/cursor binaries, no API keys) → a phone-created session run with a real harness errors after landing in the transcript. Expected/OK; documented.
- To exercise a *working* run + Watch Live→Stop, one chat is seeded over the engine IPC (ws+JSON, unauthenticated on localhost) with `config.harness='mock'` and the app runs with `ZERON_MOCK_QUESTION=1` so the run parks at `awaitingInput` (persistent "running" state). This uses the engine's built-in MockHarness — no mobile code modified. Mock chat id `14d2e83d-f387-4835-9e3d-c4102fb5b635` ("Describe what you see") confirmed `awaitingInput` via WatchSessions. Also seeded 3 idle real-harness chats for Sessions-list density.
- ComputerStatus RPC always returns a status object → `client.computer` truthy → Watch Live icon appears on session screens. CU enabled via desktop UI + Cua Driver 0.28.2 installed (187 MB); **Screen Recording granted to CuaDriver in System Settings; Accessibility left pending — per test constraints the AX password prompt was not touched.** The driver's permission gate therefore refuses all actions (`permissions_pending`) → the Watch Live stage will show the error state instead of frames; Stop remains exercisable (interrupt is independent of frames). Driver daemon must be launched via `open -a CuaDriver` (LaunchServices) for the com.trycua.driver TCC identity.
- Side finding for the lead: Cosmos writes `~/.zeron/computer/cua-driver/manifest-observe.yaml` with `schema_version: 1`, which cua-driver 0.28.2 rejects (`unknown field schema_version, expected version`) when passed via `--capability-manifest` — possible driver/manifest schema drift worth checking against the pinned release.
